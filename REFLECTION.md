Q1-Ln 128: when the input is "5." the first condition self.peek() checks the next character without moving forward then the second condition self.peek_next().is_ascii_digit() checks the next character after the decimal point is a value from 0 to 9. The first condition comes out as true and the second condition comes out as false so 5. is not treated as a number. This follows the specifation of section 1.4 that says .5 and 5. are not numbers
Q2-scan_token increments the line counter each time it reads a newline, and string does the same for newlines inside a string literal, since strings can span multiple lines. When scanning ends, run sets the EOF token's line to the line of the last token scanned, or to 1 if no tokens were produced. So if a file ends with two blank lines after its last token, EOF gets that token's line, not the file's physical last line. This is the EOF rule in section 6.1 of the specification.
